# V3 external-data milestone conclusion

**Decision: NO-GO for deployment.** The local v3 experiment is reproducible, and the v2 external baseline is frozen. The requested primary gain in real external generalization was not achieved. Existing v2 CLI/API/gateway behavior and policy remain unchanged. [Full scorecard](v3_external_scorecard.md) · [data](v3_training_data.md) · [leakage](v3_data_leakage.md) · [calibration](v3_calibration.md) · [errors](v3_error_analysis.md) · [ablation](v3_ablation.md).

1. **Why did v2 fail on TAB?** Its synthetic/Turkish-trained binary PII head misses most narrow ECHR DIRECT PERSON/CODE identifiers; the first-window classifier also confuses many public or QUASI/NO_MASK names with direct identifiers.
2. **Weakness or task mismatch?** Both. V2 produces a binary window score, whereas TAB provides typed character spans. Its 0.107 frozen F1 is a projected window-presence metric, never entity F1. Even at that compatible granularity recall is poor.
3. **Why 90% jailbreak false alarms?** The frozen head overpredicts attacks on ordinary community prompts at 0.50. Inspected errors show roleplay/imperative benign prompts and some regular-label noise. The 94-content-token limit truncates 75.6% of clean regular prompts, potentially hiding disambiguating later text. These are evidence-supported contributors, not a full causal proof.
4. **Real v3 training sources?** TAB official quality-checked train (328 cases, 6,121 windows), Lakera Gandalf official train (777 human-submitted game prompts with weak positive labels), and 1,279 CC0 prompts.chat community prompts as conservatively filtered weak benign examples. No synthetic project rows trained v3 heads.
5. **Unseen external data?** TAB official test and the frozen JailbreakLLMs community subset were never used to fit weights, calibration, or thresholds. Similar train/dev rows were removed from headline tests. The final test was inspected after the first candidate and TAB postprocessing was refined on development, so a new blind holdout is still required for a release claim.
6. **Generalization to a different source?** PII partly: TAB train to distinct ECHR test improved window ROC-AUC 0.629→0.860. Attack **no**: 111/112 same-source Gandalf test attacks were flagged, but only 22/635 independent JailbreakLLMs attacks.
7. **False positives?** On paired clean TAB windows, 131→25. On jailbreak prompts, 4,603→267. These decreases came with unacceptable missed positives.
8. **False negatives?** TAB 86→92; jailbreak 34→613. This blocks promotion.
9. **Calibration?** TAB ECE/Brier/NLL improved slightly. Jailbreak Brier 0.141→0.126 but ECE 0.119→0.121 and NLL 0.482→0.640 worsened across source.
10. **Turkish?** No independent human-labeled Turkish v3 set was available; no Turkish v3 score is claimed. Earlier v2 Turkish diagnostics do not measure v3 transfer.
11. **Which changes caused improvement?** The frozen-encoder BIO head improved TAB ranking and FPR. Code-span cleanup improved development exact code offsets. Human benign negatives reduced jailbreak FPR, but Gandalf-style positives did not cover long community jailbreaks. The calibrated threshold did not rescue transfer.
12. **What remains weak?** Person exact-span recall, direct jailbreak recall, hard benign security discussions, indirect injection, Turkish external coverage, long-input handling, and truly blind post-iteration evaluation. No v3 ONNX or UNO Q run was made.

**Recommended next milestone:** build a legally usable human-annotated, source-disjoint direct-jailbreak training/development set with long prompts and benign security discussions; allocate a *new* blind source for final testing. In parallel, fine-tune the last encoder layers for TAB span tagging using only TAB train/dev, then compare against Presidio and v2 on that new held-out source. Keep the authorization gateway fail-closed regardless of model score.
